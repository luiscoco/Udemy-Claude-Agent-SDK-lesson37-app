01

Opt in and inspect availability

Task tools depend on the bundled runtime and model. This app explicitly enables CLAUDE_CODE_ENABLE_TODO_TOOLS, selects native Task tools and shows the actual SDK initialization tool list.

02

Correlate real task IDs

TaskCreate input describes a task. Its ID comes from the correlated user tool result, in tool_use_result.task.id. Pair that result with the request through tool_use_id.

03

Track confirmed lifecycle changes

Use pending, in_progress and completed. TaskUpdate deleted removes a task. This tracker waits for successful tool results before changing confirmed state, so a denied update cannot falsely complete a task.

04

Render active work clearly

Show activeForm while a task is in_progress and subject otherwise. Count completed and in-progress tasks. Pending tasks use an open circle, not a failure symbol.

05

Compare progress with actual work

The website experiment creates home, about and stylesheet tasks, writes the three bounded files and updates progress. Inspect independently read file content; a completed checklist is an agent report, not an independent test.

06

Handle variations and failure

Read raw taskId, id or task_id and activeForm or active_form defensively. Compare TaskList, TaskGet, deletion, failed updates, the legacy TodoWrite replacement list and a real turn-limit result plus exception.
